# 系统 GDD · 经济与商店系统（Economy & Shop System）

> 范围：金币模型、商店系统、道具定义、金币钳制、购买流程
> 代码锚点：`src/lib/gold.ts`（钳制逻辑）+ `src/lib/property-data.ts`（道具常量）+ `src/app/api/shop/route.ts`（商店路由）+ 各地点 `shopItems`

---

## ① 概述

经济系统以**金币（Gold）**为核心货币，管控玩家在修仙世界中的资源获取与消费。金币通过叙事事件、地点探索、秘境奖励、街机游戏、物品出售等多种途径流入，通过商店购物、诊所治疗、炼丹炉购买等场景流出。

系统采用**双层钳制机制**：全局硬边界（0–1,000,000）+ 按境界动态单事件收益上限，防止 AI 叙事产生异常数值破坏游戏平衡。

---

## ② 设计目标

1. **流动性平衡**：保证玩家始终有"差一点就能买"的目标感，又不至于长期赤贫。
2. **境界通胀**：高阶玩家单事件收益上限随境界递增，低阶玩家不会被大额金币破坏前期体验。
3. **AI 叙事安全**：所有来自 AI 叙事产生的金币变动必须经过钳制层，防止 prompt injection 产生异常数值。
4. **多 sink 结构**：商店购物、诊所治疗、丹炉购买、未来功法购买构成多层级金币消耗通道。
5. **道具差异化**：房产（`PROPERTY_DEFS`）、家具（`FURNITURE_ITEMS`）、各地点商品构成多样化的消费目标。

## ③ 核心机制

### 3.1 金币钳制层（`src/lib/gold.ts`）

```
clampGoldDelta(delta, currentGold, maxGain?)
  │
  ├─ 1. 类型校验（非数字/NaN/±Infinity → 0）
  ├─ 2. 单事件 cap（|delta| ≤ maxGain，默认 10,000）
  ├─ 3. 下限钳制（currentGold + delta ≥ 0）
  └─ 4. 上限钳制（currentGold + delta ≤ GOLD_MAX）
```

**核心常量**：

| 常量 | 值 | 说明 |
|------|-----|------|
| `GOLD_MIN` | 0 | 金币不可为负 |
| `GOLD_MAX` | 1,000,000 | 全局封顶（TODO：建议提升至 10,000,000） |
| `GOLD_MAX_GAIN_PER_EVENT` | 10,000 | 单事件静态收益上限 |

**动态 cap 公式**（`getGoldMaxGainByRealm`）：

```
cap = GOLD_MAX_GAIN_PER_EVENT × 1.5^(min(realmLevel, 12) / 3)
```

| 境界等级 | 单事件 cap | 放大倍数 |
|---------|-----------|---------|
| 0（凡人） | 10,000 | 1.0× |
| 3（炼气中期） | 15,000 | 1.5× |
| 6（筑基后期） | 22,500 | 2.25× |
| 9（金丹巅峰） | 33,750 | 3.375× |
| 12（元婴巅峰+） | 50,625 | 5.0625× |

### 3.4 商店系统（`/src/app/api/shop/route.ts`）

**商品来源**：
- 各 `LOCATIONS` 入口定义的 `shopItems`（药品、材料、功法等）
- 全局道具池 `PROPERTY_DEFS`（房产：公寓/住宅/别墅/汽车）
- 家具池 `FURNITURE_ITEMS`

**购买流程**：
1. `POST /api/shop` 接收 `{ userId, itemId, quantity }`
2. 获取用户修炼者信息（含当前 gold）
3. 计算总价 = `item.price × quantity`
4. 校验库存（`item.stock` 或 `unlimited`）
5. 扣除金币（`gold = gold - totalPrice`）
6. 更新背包
7. 返回新余额

**安全风险**：`shop/route.ts` 直接使用 `body.userId` 而非 `requireCultivator()`，需补充所有权校验。

| 凡人期（0–16岁，无行动） | 0–500 | 无（家庭对话不可用） | 无 |

## ⑤ 玩家流程

```
[金币流入]
  叙事事件 ─→ clampGoldDelta ─→ gold += delta
  地点探索 ─→ clampGoldDelta ─→ gold += delta
  秘境通关 ─→ clampGoldDelta ─→ gold += delta
  物品出售 ─→ gold += price

[金币流出]
  商店购物 ─→ gold -= totalPrice → 背包增加道具
  诊所治疗 ─→ gold -= cost → health 恢复
  丹炉购买 ─→ gold -= price → 丹炉解锁
```

## ⑧ 风险与开放问题

### 已知风险

1. **🔴 叙事路由未处理金币变动**：`/api/narrative` 的所有 case（日常、突破、奇遇、出生）均未读取 `narrative.goldChange`，AI 返回的金币变动被静默忽略。**P0 优先**。
2. **🟡 家庭对话使用静态 cap**：`family-dialogue/route.ts` 调用 `clampGoldDelta` 时未传递 `maxGain` 参数，使用默认的 10,000，高阶玩家应使用 `clampGoldDeltaForRealm` 动态 cap。
3. **🟡 GOLD_MAX 过小**：1,000,000 封顶对于高阶玩家过小（realmLevel 12 时每次约 50k，20 次事件即可触顶），建议提升至 10,000,000。
4. **🟢 商店路由缺少所有权校验**：直接使用 `body.userId`，存在用户伪造风险。

### 开放问题

1. **金币通胀衰减**：高金币余额时 AI 产出金币是否应递减？建议设计衰减系数。
2. **审计日志**：目前无金币变动审计记录，排查异常需要 DB 日志。
3. **经济闭环**：未来是否引入"灵石"作为修仙者专属货币，与"金钱"双轨并行？
4. **跨世继承**：轮回转世时金币如何处理？完全重置 vs 部分继承？
