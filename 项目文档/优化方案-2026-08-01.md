## P0：记忆系统重构（向量 RAG）

### 现状问题

`Cultivator.storyEntries` 是一个 JSON 数组，上限 50 条，超限后 AI 压缩为 500 字摘要，仅保留重要 + 最近条目。**压缩 = 磨平细节**——玩 500 轮后，AI 对"你爸是个铁匠"的记忆只剩"你有个爸"。

### 目标

让 AI 能从全部历史记忆中检索出与当前场景最相关的 3-5 条，实现叙事连贯性——即使玩了 1000 轮，AI 还记得"你 15 岁在坊市被骗过"。

### 方案

#### 1. 新表 MemoryEntry

```prisma
model MemoryEntry {
  id              String   @id @default(cuid())
  cultivatorId    String
  title           String
  summary         String                     // 100-200 字摘要
  narrative       String?                    // 完整叙事（记忆面板展示+编辑）
  important       Boolean  @default(false)
  tags            String?                    // JSON 关键词：["坊市","交易","NPC_张三"]
  cultivatorAge   Int                        // 发生时年龄
  cultivatorRealm String?                    // 发生时境界
  embedding       String?                    // 1024 维向量 JSON 字符串（SiliconFlow BAAI/bge-m3）
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt        // 编辑时自动更新

  @@index([cultivatorId, createdAt])
  @@index([cultivatorId, important])
  @@index([cultivatorId, cultivatorAge])
}
```

#### 2. Embedding 方案

**选型**：AI 提供商的 embedding API（OpenAI 兼容 `/v1/embeddings`）

| 项 | 值 |
|----|-----|
| 方式 | 调用现有 AI 提供商的 embedding API |
| 成本 | 极低（1000 条 ≈ 几分钱） |
| 延迟 | ~100ms/条，写 entry 时异步调用，不阻塞主流程 |
| 依赖 | 零新增（复用已有 provider 基础设施） |
| 参考 | XianTu 同方案：`embeddingService.ts` → SiliconFlow BGE-M3 |

#### 3. 检索逻辑

构建 narrative context 时，三层检索注入：

```
1. 热数据（最近 5 条）→ 完整摘要，直接注入
2. 向量检索（top-3）→ 对当前行为文本生成 embedding，
   与所有 MemoryEntry 算余弦相似度，取 top-3 注入
3. tag 兜底→ 若 top-3 不足 3 条，用 tags 关键词匹配补全
```

**余弦相似度计算**：加载该 cultivator 所有 embedding，`O(n)` 遍历。1000 条 × 1024 维 ≈ 4MB，内存计算 < 20ms。

#### 4. 迁移

已有 `storyEntries` → 一次性写入 MemoryEntry + 生成 embedding。

#### 5. 写入路径

`narrative-effects.ts` 的 `storyEntry` case 修改：
- 写 `Cultivator.storyEntries`（保持热数据，上限 50 条）
- 写 `MemoryEntry`（无上限）
- 提取 tags（从 actionId/locationId/NPC 名自动提取）
- 生成 embedding（异步，不阻塞主流程）

#### 6. 文件改动清单

| 文件 | 改动 |
|------|------|
| `prisma/schema.prisma` | 新增 MemoryEntry 模型 |
| `src/lib/embedding.ts` | **新建**：embedding 服务（API 调用封装 + 向量缓存） |
| `src/lib/narrative-effects.ts` | storyEntry case：同步写 MemoryEntry + embedding |
| `src/lib/narrative-context.ts` | `buildNarrativeContext`：加入向量检索 top-3 |
| `src/lib/narrative.ts` | `buildSummaryFromEntries`：改为三层格式输出 |
| `src/app/memory/page.tsx` | **新建**：记忆面板页面（列表 + 查看 + 编辑） |
| `src/app/api/memory/route.ts` | **新建**：记忆 CRUD 路由 |

## P1：本地缓存 IndexedDB

### 现状问题

每次刷新页面：`fetch /api/cultivator` → 服务端 Prisma 查 50+ 字段 → 网络回传 → 渲染。用户看到"加载中…"。

### 方案

用浏览器原生 IndexedDB 缓存 cultivator 数据，通过 `idb` 库封装。

```typescript
// src/lib/cache.ts
import { openDB } from 'idb';

const DB_NAME = 'cultivation-cache';
const STORE_NAME = 'cultivator';
const CACHE_VERSION = 1;

export async function getCachedCultivator(userId: string) {
  const db = await openDB(DB_NAME, 1, {
    upgrade(db) { db.createObjectStore(STORE_NAME, { keyPath: 'id' }); },
  });
  const result = await db.get(STORE_NAME, userId);
  return result?.data ?? null;
}

export async function setCachedCultivator(userId: string, data: unknown) {
  const db = await openDB(DB_NAME, 1, {
    upgrade(db) { db.createObjectStore(STORE_NAME, { keyPath: 'id' }); },
  });
  await db.put(STORE_NAME, { id: userId, data, version: CACHE_VERSION, updatedAt: Date.now() });
}
```

**缓存策略**：
- `loadCultivator`：先读缓存 → 秒渲染 → 异步 fetch 最新数据 → 覆盖缓存
- `setCultivator`：更新状态 → 同步写缓存
- 版本号递增 → 强制全量刷新

### 改动清单

| 文件 | 改动 |
|------|------|
| `src/lib/cache.ts` | **新建**：IndexedDB 缓存封装（`idb` 库） |
| `src/store/game-actions.ts` | `loadCultivator`：先读缓存再 fetch |
| `src/store/game-helpers.ts` | `deriveStoreFields`：同步写缓存 |
| `package.json` | 加 `idb` 依赖 |

## P2：存档备份与恢复

### 现状问题

单存档，SQLite 文件损坏、手滑操作、想回溯——都只能从头来。

### 方案：A（主动备份）+ B（自动备份）

#### A. JSON 导出/导入（玩家主动操作）

**导出**：`POST /api/backup/export`
- 全量导出：Cultivator + FamilyMember + GameEvent + MemoryEntry → JSON
- 返回文件下载

**导入**：`POST /api/backup/import`
- 上传 JSON 文件
- 服务端校验格式
- 事务内覆盖当前数据
- 导入前自动创建当前存档的备份

**前端**：设置弹窗加两个按钮——"导出存档"、"导入存档"

#### C. 自动备份（系统兜底）

**触发时机**：每次 action 成功后，自动导出 JSON 备份存服务端。

**存储**：`prisma/backups/` 目录，保留最近 5 份。

**自动清理**：超过 5 份时删除最旧的。

#### D. 恢复界面

`/backups` 页面：
- 列表显示可用备份（时间戳 + 年龄 + 境界）
- 点击恢复 → 确认 → 覆盖当前存档 → 刷新

### 改动清单

| 文件 | 改动 |
|------|------|
| `src/app/api/backup/export/route.ts` | **新建**：导出路由 |
| `src/app/api/backup/import/route.ts` | **新建**：导入路由 |
| `src/app/backups/page.tsx` | **新建**：备份管理页面 |
| `src/app/settings/page.tsx` | 加导出/导入按钮 |
| 自动备份脚本 | 在 action-service 中加自动备份钩子 |

## P3：内容扩展方向

### 优先级排序

| 优先级 | 方向 | 价值 | 成本 | 说明 |
|--------|------|------|------|------|
| ⭐⭐⭐ | NPC 关系网络 | 高 | 中 | 让社交有深度，亲密度不再是数字 |
| ⭐⭐⭐ | 世界事件系统 | 高 | 中 | 让世界动起来，玩家有期待感 |
| ⭐⭐ | 功法深度扩展 | 中 | 中 | 增加 build 多样性 |
| ⭐⭐ | 宗门/势力 | 中 | 高 | 后期归属感，但现代背景不太适配 |
| ⭐ | 多世界观 | 低 | 高 | 当前不急需 |

### P3-A：NPC 关系网络

**现状**：`npcRelations: Record<string, number>`——只有亲密度数字，没有关系类型和历史。

**目标**：图结构关系网络，每个 NPC 有：
- 关系类型（家人/朋友/仇人/恋人/师徒/同门）
- 关系历史（事件列表，如"张三在坊市帮了你"）
- NPC 之间的关系（"张三和李四有仇"）

**实现路径**：
1. 新建 `NpcRelation` 表（类似 MemoryEntry 的轻量结构）
2. 在叙事效果中增加 `npcRelation` 效果类型
3. 前端在关系页面显示关系网络图

**从 XianTu 参考**：`npcRelationNetwork.ts` 的 nodes + edges 结构

### P3-B：世界事件系统

**现状**：世界是静态的，只有玩家行动驱动变化。

**目标**：周期性世界事件，让世界有生命感：
- 灵气潮汐（每季度/每年触发，影响修炼速度）
- 妖兽袭击（城市安全事件，可参与防守）
- 秘境开启（限时探索，高回报）
- 拍卖会（稀有物品流通）
- 新闻事件（天气异常、名人突破、势力变动）

**实现路径**：
1. 新建 `WorldEvent` 表 + 事件池
2. `advance-quarter` 中触发世界事件检测
3. 前端通知栏显示当前世界状态

### P3-C：功法深度扩展

**现状**：3 装备槽 + 熟练度升级，效果是数值加成。

**目标**：功法树 + 技能解锁 + 组合效果：
- 每门功法有独立技能树（5-10 个技能节点）
- 功法组合产生 synergy 效果
- 功法相克（五行生克）

**从 XianTu 参考**：`thousandDaoData.ts` 的三千大道体系

### P3-D/E：宗门与多世界观

**建议延后**。宗门在现代都市修仙背景中需要重新设计（改为"修仙者协会/事务所"？），多世界观需要大量内容填充。先把前三个做好。

## 不做的事项

| 事项 | 理由 |
|------|------|
| 多存档槽（多角色） | 单角色深度养成 > 多角色浅尝辄止，当前架构不适合 |
| 多语言 i18n | 中文叙事游戏，无此需求 |
| SillyTavern 兼容 | 独立 Web 应用，不需要嵌入酒馆 |
| 在线多人 | 单机养成，不需要 |
| 全内联打包 | Next.js 架构不支持，也不必要 |
