# 🚑 设计急救清单（Design First-Aid Checklist）

> 快速定位 & 解决常见设计-代码偏差问题的操作卡片。
> 每条卡片格式：**症状 → 诊断 → 处方 → 验证**。

---

## T0 — 紧急（P0，阻塞生产）

### T0-1：/api/narrative 没有处理 goldChange

**症状**：玩家从日常修炼/突破/奇遇叙事中获得的 AI 推荐金币奖励全部丢失。

**诊断**：`narrative/route.ts` 中所有 case（BIRTH、DAILY_CULTIVATION、BREAKTHROUGH、ENCOUNTER、default）均未读取 `narrative.goldChange`。

**处方**：
1. 在路由各 case 中添加 `const goldEffect = extractEffectsByKind(narrative, "gold");`
2. 调用 `clampGoldDelta` 钳制后更新 `c.gold`
3. 或迁移到 Phase 2 统一使用 `applyEffects()`

**验证**：通过 `curl POST /api/narrative -d '{"type":"DAILY_CULTIVATION"}'` 检查返回数据中是否包含 `goldChange` 字段，且 DB 中 gold 是否有变化。

---

### T0-2：类型定义重复（narrative-types.ts vs narrative.ts）

**症状**：修改 `narrative-types.ts` 中的类型后编译通过，但运行时类型不匹配（因为 `narrative.ts` 有另一套副本）。

**诊断**：`narrative.ts` 第 417-499 行重新定义了 `NarrativeBase`、`RegularNarrative`、`EncounterNarrative`、`NPCDialogueNarrative`、`FamilyDialogueNarrative`、`BirthNarrativeResult`。

**处方**：
1. 删除 `narrative.ts:417-499` 的重复类型定义
2. 将所有消费者的 import 改为 `from "@/lib/narrative-types"`
3. 确保 `NarrativeBase` 包含 `goldChange?: number` 字段

**验证**：`grep -n "interface NarrativeBase\|interface RegularNarrative\|type UnifiedNarrative" src/lib/narrative.ts` 应返回空。

---

### T0-3：体力预扣无回滚

**症状**：家庭对话 AI 调用失败后体力已消耗。

**诊断**：`family-dialogue/route.ts:58-60` 在 AI 调用前执行 `stamina: { decrement: 1 }`，失败分支未恢复体力。

**处方**：
1. 将体力扣除移到 AI 成功返回后
2. 或在 catch 块中 `prisma.cultivator.update({ data: { stamina: { increment: 1 } } })`

**验证**：模拟 AI 调用失败场景，检查 stamina 是否恢复到调用前值。

---

## T1 — 高优先级（P1，即将阻塞）

### T1-1：Gold cap 未按 realm 动态

**症状**：高阶玩家家庭对话仍然只有单次 10,000 金币上限。

**诊断**：`family-dialogue/route.ts:98` 调用 `clampGoldDelta(result.goldChange, c.gold)` 使用默认 maxGain=10,000，应使用 `clampGoldDeltaForRealm(result.goldChange, c.gold, c.realmLevel)`。

**处方**：
```
// 修改前
clampGoldDelta(result.goldChange ?? 0, c.gold ?? 0)
// 修改后
clampGoldDeltaForRealm(result.goldChange ?? 0, c.gold ?? 0, c.realmLevel ?? 0)
```

**验证**：创建不同 realmLevel 的测试 cultivator，调用家庭对话，检查 gold 变动上限是否符合 `getGoldMaxGainByRealm` 公式。

---

### T1-2：GOLD_MAX 封顶 1M 过小

**症状**：高阶玩家多次高效事件后金币轻易触顶。

**诊断**：`gold.ts:9` 定义 `GOLD_MAX = 1_000_000`。按 realmLevel 12 时 50k/事件计算，仅需 20 次事件即可触顶。

**处方**：
```
// gold.ts:9
GOLD_MAX = 10_000_000
```

**验证**：运行 `clampGoldDelta(1_000_000, 9_500_000)` 应返回 500,000 而非 0。

---

### T1-3：商店路由缺少所有权校验

**症状**：任何知道用户 ID 的人可替他人购买商品。

**诊断**：`shop/route.ts` 使用 `body.userId` 直接查询，未使用 `requireCultivator()` 进行认证。

**处方**：
```typescript
// 修改前
const { userId, itemId, quantity } = await request.json();
const user = await prisma.user.findUnique({ where: { id: userId } });
// 修改后
const { itemId, quantity } = await request.json();
const c = await requireCultivator(request);
// 使用 c.id 而非 userId
```

**验证**：尝试使用他人的 x-user-id 发送购买请求，应返回 401。

### T2-2：亲密度无极值衰减
